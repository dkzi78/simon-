# MILESTONES — סיימון

תוכנית פיתוח המבוססת על [PRD.md](PRD.md), ‏[ARCHITECTURE.md](ARCHITECTURE.md) ו־[DESIGN.md](DESIGN.md). אבני הדרך מסודרות לפי תלות: תשתית הרצה, משחק שלם, אודות והישגים עם המשכיות משחק, PWA ו־Offline, ולבסוף פריסה ואימות במובייל.

הפיתוח נשאר Frontend בלבד ובשני מסכים. אין Backend, Database או Database Migrations. סביבת הפיתוח היא מקומית; Production הוא אתר סטטי ב־GitHub Pages. יצירת מסמך זה אינה התחלת פיתוח או אישור פרסום.

## Development Execution Rules — כללי ביצוע הפיתוח

הנחיות מחייבות ל־AI שיבצע את הפיתוח:

1. יש לפתח את ה־Milestones לפי הסדר המוגדר במסמך. אין להתחיל יכולות של אבן הדרך הבאה לפני אישורה.
2. לאחר השלמת כל Milestone, יש **לעצור את הפיתוח** ולהציג למשתמש את התוצר שעובד, דרך ברורה לפתיחתו או לבדיקתו, ואת תוצאות הבדיקות מול כל סעיפי ה־Definition of Done.
3. **אין להתחיל בפיתוח ה־Milestone הבא ללא אישור מפורש של המשתמש.** סיום בדיקות או היעדר תגובה אינם אישור.
4. הדיווח יפריד בין סעיפים שעברו, נכשלו ולא נבדקו. אין לסמן אבן דרך כהושלמה אם תנאי נדרש נכשל או טרם אומת. כשבדיקה דורשת מכשיר או גישה שאינם זמינים ל־AI, יש להדריך את המשתמש בבדיקה ולהמתין לתוצאה.
5. בכל אבן דרך יש לשמור על היכולות שכבר אושרו: להריץ את ה־Unit Tests, לבדוק ידנית בדפדפן בגודל מובייל שהזרימות הקודמות עדיין עובדות, ולתקן כשלים לפני הצגת התוצר לאישור. אין בדיקות דפדפן אוטומטיות (ראו ADR-1 ב־ARCHITECTURE.md).
6. משתמשים ב־Stack שנבחר ובמקורות העיצוב הקיימים. אין להוסיף מסכים או יכולות, לשנות את כללי המשחק או לפרסם Repository קיים כציבורי ללא הסכמה מתאימה. אם דרושה פעולת חשבון שאין ל־AI אפשרות לבצע, מדריכים את המשתמש צעד אחר צעד בשפה פשוטה.
7. פריסה אוטומטית מופעלת באבן דרך 5. לאחר הפעלתה, כל שינוי שנדחף ל־`main` יכול להתפרסם; יש להעביר לשם רק גרסה שהמשתמש אישר לפרסום. אישור מעבר לאבן דרך אינו מחליף את עצירת הסיום שלה.

## Milestone 1 — פרויקט ניתן להרצה ולבדיקה ✅

**שם ומטרה:** הקמת בסיס טכני מינימלי המאפשר לפתח ולבדוק את האפליקציה בצורה עקבית. זוהי אבן דרך טכנית מקדימה, לפני ה־Vertical Slices של המשחק.

**מה יש לממש:**

- פרויקט `vanilla-ts` עם Vite, ‏TypeScript במצב `strict`, ‏CSS רגיל, Node.js 24 LTS ו־npm, בהתאם למדיניות הגרסאות שבארכיטקטורה. ה־Git Repository המקומי והחיבור ל־GitHub כבר קיימים.
- Lockfile ופקודות להתקנה עקבית, Development, ‏Type Checking, ‏Unit Tests, ‏Build ו־Preview.
- עמוד פתיחה מינימלי בעברית וב־RTL, כדי לאמת שהאפליקציה נפתחת במובייל. אין להציג בו משחק מדומה או כפתור פעולה שאינו עובד.
- תשתית Vitest עם בדיקה לדוגמה אחת. אין CI ואין פרסום Pages באבן דרך זו.

**תוצר מצופה:** פרויקט שניתן להתקין, לפתוח בדפדפן ולבנות לאתר סטטי; מסך מינימלי לבדיקה, שעדיין אינו משחק.

**Definition of Done:**

- [ ] התקנה באמצעות `npm ci` מצליחה, עם הגרסאות המקובעות ב־Lockfile.
- [ ] Development ו־Preview של ה־Build נפתחים ומציגים עברית תקינה, `lang="he"` ו־`dir="rtl"`, ללא שגיאות בקונסולה.
- [ ] Type Checking ו־Build עוברים ונוצר `dist/`.
- [ ] `npm test` מריץ את Vitest ובדיקת הדוגמה עוברת.
- [ ] אין תלות בשרת או במסד נתונים.

## Milestone 2 — משחק שלם במסך הבית ✅

**שם ומטרה:** לאפשר למשתמש להתחיל משחק, לחזור על רצפים, להפסיד או להשלים 10 שלבים ולשחק שוב, עם עיצוב ושמע מחוברים מקצה לקצה.

**תלות:** אישור Milestone 1.

**מה יש לממש:**

- מסך בית לפי DESIGN וה־Mockup: כותרת, כותרת משנה, ארבעה ריבועים מעוגלים ב־Grid של 2×2 וכפתור „התחל”. צבעי הלוח ומיקומיהם, Heebo מקומי, ההצללות, תוויות הצבעים ו־Focus בהתאם לעיצוב.
- Game Engine, ‏Controller, ‏State Machine, ‏Playback Scheduler ו־Audio Adapter לפי גבולות האחריות בארכיטקטורה.
- רצף אקראי מצטבר, שלבים 1–10, בדיקת קלט, חסימת קלט בזמן הצגה, סיום בטעות הראשונה והיעדר מגבלת זמן לתשובה.
- תזמון קבוע: 600 ms לצבע ו־300 ms בין צבעים; ההפסקה בין שלבים לפי הארכיטקטורה. ארבעה צלילים שונים באמצעות Web Audio, הפעלה מתוך Gesture וטיפול בכשל שמע.
- שלב נוכחי ומצב תור; הודעת סיום, תוצאה ו„שחק שוב” באותו מסך. מצבים שאינם מצוירים ב־Mockup משתמשים בשפה העיצובית הקיימת, ללא מסך חדש.
- ביטול פעולות מתוזמנות באמצעות Generation והשהיה בעת הסתרת המסמך, עם הצגת רצף השלב מחדש בחזרה.

**תוצר מצופה:** משחק מקומי שלם ומעוצב במסך הבית. שמירת הישגים ומסך אודות מתחברים באבן הדרך הבאה; בשלב זה אין להציג ניווט לאודות כפעיל אם אינו ממומש.

**Definition of Done:**

- [ ] Unit Tests מאמתים הוספת צבע אחד ללא שינוי הרצף הקודם, חזרות צבע מותרות, ניקוד של שלבים שהושלמו בלבד, הפסד בטעות הראשונה, ובאקראיות נשלטת השלמה של בדיוק 10 שלבים ללא שלב 11.
- [ ] בדיקה ידנית: אפשר לשחק מהתחלה ועד הפסד, ולאחר מכן להתחיל שוב. הקצב אחיד; לחיצה בזמן הצגת הרצף או אחרי סיום אינה משנה דבר.
- [ ] בדיקה ידנית: לחיצות מהירות נקלטות לפי הסדר, בלי לחיצה כפולה ובלי השלמת שלב כפולה.
- [ ] ארבעת הצלילים וההדגשות פועלים מתוך התחלה בלחיצה; בכשל שמע מוצגת „הצלילים אינם זמינים כעת” והמשחק החזותי ממשיך.
- [ ] חזרה מרקע מציגה מחדש את רצף השלב ללא כישלון או צליל ישן. רענון מחזיר למצב „התחל”.
- [ ] המסך בגודל מובייל תואם ל־DESIGN מבחינת מבנה, RTL, מיקום הצבעים וקריאות. אין גלילה אופקית; אזורי המגע לפחות 48 px.
- [ ] Type Checking, ‏Unit Tests ו־Build עוברים.

## Milestone 3 — אודות, הישגים והמשך משחק לאחר ניווט ✅

**שם ומטרה:** לאפשר למשתמש לעיין בהוראות ובהישגים ולחזור לשלב הנוכחי בלי לאבד את המשחק.

**תלות:** אישור Milestone 2.

**מה יש לממש:**

- מסך אודות בעיצוב המוגדר: אזור לוגו תואם ל־Mockup, תיאור, הוראות ושני כרטיסים אופקיים של „שיא אישי” ו„תוצאת המשחק האחרון”. התאמת נכס הלוגו המוקדם למראה המוגדר ב־DESIGN נכללת כאן.
- Bottom Navigation בשני המסכים, „בית” מימין ו„אודות” משמאל, עם אייקונים וסימון פעיל. Hash Navigation עבור `#/` ו־`#/about`, תמיכה ב־Back ונרמול Hash לא מוכר לבית.
- השהיה בכניסה לאודות והצגת כל רצף השלב מחדש בחזרה, כולל כניסה בזמן הצגה, קלט חלקי או הפסקה בין שלבים.
- Score Repository ו־Local Storage: JSON אחד עם שני ערכי הניקוד בלבד, Validation ו־Fallback בזיכרון.
- חיבור כתיבת ההישגים לכל הצלחה או הפסד לפי הכללים, ללא שמירת רצף או משחק פעיל.

**תוצר מצופה:** שני מסכים מעוצבים ועובדים; משחק שניתן להשהות באמצעות ניווט; תוצאות שמתעדכנות תוך כדי משחק ונשמרות בין הפעלות.

**Definition of Done:**

- [ ] שני המסכים תואמים למבנה ולעיצוב המוגדרים. הלוגו, התיאור, ההוראות והכרטיסים זמינים; תוכן ארוך ניתן לגלילה ואינו מוסתר מאחורי הניווט.
- [ ] ניווט באמצעות הפריטים ובאמצעות Back מעדכן את המסך ואת הסימון הפעיל. אין מסך שלישי או קישור פעיל ללא יעד עובד.
- [ ] מעבר לאודות בכל שלב של Playback או הזנה עוצר צלילים ופעולות מתוזמנות. בחזרה מוצג אותו רצף מתחילתו, ללא קלט חלקי וללא הגרלה נוספת עקב החזרה.
- [ ] נבדקו גם מעבר בין שלבים, שהייה באודות בזמן הסתרת האפליקציה וחזרה ממצבי התחלה וסיום; אין חידוש משחק שכבר הסתיים.
- [ ] Unit Tests מאמתים את תרחיש הניקוד עם ערכים שמורים `bestScore=7` ו־`lastScore=5`: התחלה משאירה אותם; השלמת שלב 1 מעדכנת תוצאה ל־1 ושומרת שיא 7; השלמת שלב 8 מעלה את השיא ל־8. כישלון לפני הצלחה ראשונה שומר 0 ללא מחיקת השיא; השלמת כל המשחק שומרת 10.
- [ ] Unit Tests מאמתים שנתונים חסרים, JSON פגום ושדות שאינם מספרים שלמים בטווח 0–10 מוצגים כ־0, ושכשל אחסון אינו מפיל את המשחק.
- [ ] בדיקה ידנית: רענון באמצע משחק ופתיחה מחדש של הדפדפן שומרים את שתי התוצאות ומחזירים משחק למצב התחלתי.
- [ ] Type Checking, כל ה־Unit Tests ו־Build עוברים.

## Milestone 4 — PWA ומשחק מלא ב־Offline ✅

**שם ומטרה:** לאפשר התקנה בנייד והפעלה מחדש של המשחק ללא אינטרנט לאחר הכנה מוצלחת, תוך שמירת רציפות משחק בעת עדכון גרסה.

**תלות:** אישור Milestone 3.

**מה יש לממש:**

- Manifest בעברית וב־RTL, ‏Standalone, ‏`id` יציב, ‏`start_url` לבית ו־Scope לפי Base Path של הפרויקט.
- אייקונים מקומיים לפי הארכיטקטורה: 192×192, ‏512×512, ‏Maskable ו־`apple-touch-icon` בגודל 180×180, המבוססים על הלוגו המעודכן.
- `vite-plugin-pwa` עם Workbox ‏`generateSW`, ‏Precache מלא לשני המסכים, הגופן, הלוגו והאייקונים, ו־Cache ID מוגבל לפרויקט.
- מדיניות עדכון ממתינה: `registerType: "prompt"`, ‏`skipWaiting: false`, ללא Reload במהלך משחק וללא UI חדש לעדכון או התקנה.
- הפרדת Dev מ־Build: ה־Service Worker כבוי ב־Dev; בדיקת ה־Offline הידנית נעשית על Build מוגש ב־localhost וב־Base Path המתוכנן לפריסה.

**תוצר מצופה:** Build מוכן ל־PWA ול־Offline, שניתן לבדוק מקומית או בכתובת HTTPS לבדיקות, לפני פריסת Production.

**Definition of Done:**

- [ ] Manifest, האייקונים, ה־Scope ונתיבי הנכסים תקינים תחת נתיב הפרויקט, והדפדפן מזהה את האתר כניתן להתקנה. הפעלה דרך `start_url` פותחת את הבית במצב התחלתי.
- [ ] רשימת ה־Precache ב־Build כוללת את כל משאבי שני המסכים, הגופן, הלוגו והאייקונים. אין תלות ב־CDN, גופן מרוחק או הורדת שמע.
- [ ] בדיקה ידנית: אחרי טעינה מלאה ברשת, ניתוק האינטרנט ופתיחה מחדש — המשחק, הצלילים, המעבר לאודות, הלוגו והשמירה פועלים.
- [ ] תצורת העדכון היא `registerType: "prompt"` ו־`skipWaiting: false`, ללא Reload אוטומטי.
- [ ] Type Checking, כל ה־Unit Tests ו־Build עוברים, והזרימות מאבני הדרך הקודמות עדיין עובדות.

## Milestone 5 — פריסה אוטומטית ואימות במכשירים אמיתיים

**שם ומטרה:** להעמיד את המוצר המלא באתר HTTPS חי ב־GitHub Pages, עם פרסום אוטומטי מבוקר ואימות חוויית המובייל וה־PWA.

**תלות:** אישור Milestone 4. הפעלת הפרסום מבוצעת במסגרת אבן דרך זו לאחר שהמשתמש מאשר את הגרסה לפרסום.

**מה יש לממש:**

- הגדרת GitHub Pages לפרסום באמצעות GitHub Actions, ‏Environment בשם `github-pages` וכתובת האתר המתאימה ל־Repository.
- התאמת Vite Base Path, כתובות נכסים, Manifest ו־Service Worker לכתובת החיה; אותה תצורת נתיבים משמשת בבדיקת ה־Build.
- Workflow שמריץ התקנה מה־Lockfile, ‏Type Checking, ‏Unit Tests ו־Build, ומפרסם `dist/` רק בהצלחה, בכל Push ל־`main`.
- הרשאות פריסה מצומצמות ו־Concurrency למניעת פריסות מתחרות, לפי הארכיטקטורה.
- בדיקה ידנית באתר החי ובטלפון של המשתמש, כולל שמע, ניווט, חזרה מרקע, התקנה ופתיחה ב־Offline.
- תיעוד קצר להפעלה, לפריסה ולשחזור גרסה באמצעות Revert ופריסה חוזרת.

**תוצר מצופה:** קישור HTTPS למוצר המלא, פרסום אוטומטי מ־`main`, וגרסה שנבדקה בטלפון.

**Definition of Done:**

- [ ] המשתמש מקבל קישור לאתר החי ולקוד ב־GitHub. הנראות של ה־Repository תואמת לבחירה המפורשת שלו.
- [ ] Push ל־`main` מפעיל בדיקות ופריסה אוטומטית מוצלחת. כשל בבדיקות או ב־Build עוצר את הפרסום ומשאיר את הגרסה החיה הקודמת.
- [ ] האתר החי נטען ב־HTTPS; פתיחת הבית והאודות ישירות ורענון בכל אחד מהם אינם גורמים ל־404 או לאובדן נכסים.
- [ ] בטלפון של המשתמש: התקנה בדרך הנתמכת, פתיחה מהאייקון, ארבעת הצלילים, לחיצות מהירות, חזרה מרקע, קריאות עברית ו־RTL, ושימוש בשני המסכים ללא אינטרנט לאחר טעינה ראשונה.
- [ ] התיעוד הקצר להפעלה, לפריסה ולשחזור גרסה קיים ב־Repository.
